# dsh-wisp

DeepSeek Harness Web 界面的浮动陪伴插件：**DeepSeek娘** 桌宠。

**当前版本 `0.6.0`** · 零依赖 · 单文件客户端半包（精灵图内嵌为 data URI）

> 非官方插件，与 DeepSeek（深度求索）官方无关。角色形象与图片许可见 [NOTICE.md](NOTICE.md)。

---

## 它做什么

| 行为 | 触发条件 |
|---|---|
| 漂浮与呼吸 | 常驻（`prefers-reduced-motion` 下停止） |
| `idle` 青色 | 默认 |
| `alert` 琥珀色 | Agent 正在跑（出现「停止生成」按钮）**或** 输入框里有字 |
| `happy` 粉色 | 戳她一下 / 双击 / **一轮跑完** |
| `sleep` 灰色冒 `z` | 静置 `sleepAfterMs`（默认 90 秒）；任意输入唤醒 |
| `attn` 举手招你过来 + 暖红轻推 | **有东西在等你处理**：Agent 提问 / 计划待确认 / 工具授权待批准。优先于其余一切状态，睡着了也会被叫起来 |
| 她记着你 | 她会记住**一起多少天**、你常把她放在**哪个角**、常让她**穿哪套** —— 够格的时候说出来（第 2/7/14/30/100 天；某个角用过 ≥8 次且占多数；某套皮肤换过 ≥6 次）。**同一条一辈子只说一次、一天最多一句** |
| 今日里程碑 | 她数着**今天跑完多少轮**（跨刷新记着，按天归零）：到 **10 / 25 / 50 / 100 / 200 / 500** 时会用得意的表情报出数字。同一个里程碑一天只说一次 |
| 久坐提醒 | 连续活动到 `careAfterMs`（默认 **90 分钟**）她会抬手指你一下、说一句叫你起来动动。中间停顿不到 90 秒不算离开；睡着时会被叫醒再提醒；`0` = 关 |
| 时段招呼 | 挂载时的问候按**当前时段**取：早上 / 下午 / 晚上 / 凌晨四套池子，口气不同（`__wisp.doctor()` 会报当前用的是哪一套） |
| 滚轮调大小 | **Ctrl/⌘ + 滚轮**在她身上滚 = 放大/缩小一档（0.25）。**普通滚轮照常滚动页面** —— 她占地不小，直接吞掉滚轮等于在她身上把页面滚动禁掉 |
| 键盘挪位置 | 她拿到焦点后**方向键**微调 16px（**Shift = 4px**），与拖动共用同一套边界夹紧与位置记忆。在这之前挪动她**只能靠鼠标拖** |
| 躲起来之后 | 迷你小按钮**右键**也能打开同一个菜单；菜单里那一项是**开关** —— 躲着时显示「回来吧」，在着时显示「先躲起来」 |
| 右键菜单 | 右键她本体弹出四段：动作（说句话 / 放大一点 / 缩小一点 / 先躲起来 / 睡一会儿）+ **行为**（自己溜达 / 跟随状态 / 跑完撒花，带勾）+ **位置**（四个角落）+ **皮肤**。Esc、点别处、滚动都会关掉，↑↓ 可选 |
| 出错反应 | 一轮跑完时如果出现失败行（`[data-error="true"]`），她会切到 `worried` 表情说一句「好像不太顺。」，3.5 秒后恢复。同一批错误只说一次 |
| 先躲起来 | 菜单里选「先躲起来」后她整个消失，只在右下角留一个 56px 迷你按钮（用当前皮肤的图），点一下回来。状态记在本地，刷新后仍然躲着 |
| 拖动 | 按住本体拖动，带边界约束；**松手即记住位置**，下次刷新回到原处 |
| 说话 | 挂载问候、点击、睡着、醒来、跑完各有一组台词 |

外层 `pointer-events:none`，只有本体可点 —— 它不会挡住你对应用的操作。

## 文件结构

```
dsh-wisp-plugin/
├── package.json          dsh.bundle.patch + dsh.client.platform，零依赖
├── cordis.patch.yml      插入一行 host 入口（指向 dsh-wisp，绝不能是 dsh-wisp/client）
├── lib/
│   ├── index.js          host 半包：刻意为空的 ES 模块
│   ├── client.template.js  浏览器半包源码（唯一需要编辑的文件）
│   └── client.js         由 build.mjs 生成，勿手改
├── assets/               四张 256x384 透明 WebP（idle / happy / sleepy / work）
├── build.mjs             注入精灵图 + 三道构建防线
├── verify-wisp.mjs       预检：两套契约 + 真实执行
├── NOTICE.md             角色来源与许可
└── README.md             本文件
```

## 构建与预检

```bash
node build.mjs        # 把 assets/*.webp 注入 lib/client.template.js → lib/client.js
node verify-wisp.mjs  # 预检；exit 0 = 两半包都符合契约
```

**改了 `client.template.js` 就必须重新 `build.mjs`** —— `client.js` 是生成物。

`build.mjs` 现在有四道防线，任何一道失败都拒绝写出文件：

1. 占位符 `__SPRITES_LITERAL__` 必须恰好出现一次，且替换后不得残留；
2. 注入后的 `SPRITES` 表要**真的被求值**，四个 key 都必须是 `data:image/` 开头；
3. 产物**不得调用被陷阱的全局**（`setTimeout` / `setInterval` / `clearTimeout` / `clearInterval` / `fetch` / `require`）；
4. `const VERSION` 必须与 `package.json` 的 `version` 一致（防止版本漂移）。

`verify-wisp.mjs` 在真实契约下执行浏览器半包：六个被陷阱的全局以**抛异常**的形式注入，虚拟时钟同时驱动两条调度路径，假 DOM / Blob / localStorage（含"抛异常的存储"这一档）齐全。当前 **248 项全 PASS，exit 0**。

## 真实浏览器冒烟

假 DOM 能验契约，验不了**布局与合成**。本项目的三个真 bug（躲起来后气泡悬空、菜单越界、
`display:none` 是否真的让她不挡点击）全都只有真实浏览器能发现，所以这些检查留在仓库里：

```bash
node tools/smoke.mjs           # 46 项：挂载 / 菜单几何与键盘入口 / 躲起来 / 换皮肤 / attn / worried / 踱步 / 内存 / 体积
node tools/smoke.mjs --headed  # 看着它跑
```

**退出码是有意义的**：`0` 通过；`1` 有检查没过；`2` 环境中断。

headless Chromium 在内存压力下会被关掉，表现为随机的 "Target page, context or browser has
been closed"。它与本插件的正确性无关，所以脚本**只对这类中断重试一次**，两次都中断就以 2 退出 ——
`1` 永远意味着"有检查没过"。不要因为它偶发就把断言放宽，那会把真正的产品问题一起放过。

为此每个浏览器只驻留一个页面：每个页面都要装下这份包与解码后的精灵图，多开一个就是多一份。
（这条是被真实崩溃逼出来的：原来踱步那节另开一个页面，随即开始随机崩溃。）

Playwright 是**可选依赖**：找不到就以 0 退出并说明原因 —— CI 上不该因为缺浏览器而红。
pnpm 布局下顶层没有 `playwright-core` 这个名字（只有 `.pnpm/playwright-core@<ver>/`），
所以脚本会显式扫 `.pnpm`。

## 打包与分享

```bash
node tools/pack-check.mjs
```

一条命令跑完：`npm pack` → 解包 → **从解出的副本**跑预检与重建，然后逐项确认发布子集自足
（`lib/index.js` / `lib/client.js` / `cordis.patch.yml` / `assets` 都在）。

**为什么不能靠"我看过 files[] 了"**：包里的文档指向包外、`tools/` 少声明一个、素材没打进去 ——
这些都要真的解出副本才暴露。这个检查第一次跑就抓到了 README 里指向开发机绝对路径的死引用。

当前包：**164 个文件 / 19 MB**，其中 `assets/` 占 140 个文件、14.0 MB —— 但**运行时只会读其中 35 张**：

| 素材 | 数量 | 体积 | 运行时 |
|---|---|---|---|
| 默认档 1024×1536 | 35 | 3.8 MB | ✅ 就这一档被 base64 进 JS（5.2 MB） |
| `_hi` 2048×3072 | 35 | 8.1 MB | ❌ 从不读取 |
| `_md` 512×768 | 35 | 1.5 MB | ❌ 从不读取 |
| `_sm` 256×384 | 35 | 0.6 MB | ❌ 从不读取 |

后三档加起来 **105 个文件 / 9.9 MB**，唯一用途是「哪天想用 `node build.mjs --tier=hi   # 需要先 --all-tiers 生成 _hi；缺档会自动回退到默认档` 换个档重新打包」。
而且 `_hi` 连**画质收益都测不出来**（见下面性能小节：DPR 2 下高频能量差 0.3%，DPR 1/3 下 1024 档反而高 4~5%）。
**这 9.9 MB 已经省掉了**（2026-09-30）：`assets/` 现在只有默认档 35 个文件 / 3.8 MB，
包从 19 MB 降到 **9 MB**。

要生成别的档位（例如想用 `--tier=hi` 重打包）先跑：

```bash
node tools/assets.mjs --from <绿幕母版目录> --skin <皮肤> --all-tiers   # 默认**只写进包那一档**
```

流水线的默认行为已经改成"只写会进包的那一档"，所以这 9.9 MB 不会下次跑一遍又长回来。

（历史原因：这段原本写的是「4 套皮肤 × 7 情绪 = 112 张、14.6 MB」，那是第五套皮肤 `canon` 加进来之前的数字。）
classic 皮肤的绿幕原图已经不在了，那些分档是**唯一**的重建来源，所以 `build.mjs --tier=…` 在
别人的机器上仍然可用。

## 自检：`__wisp.doctor()`

她依赖的每一个选择器都是**读 DSH 源码推出来的**，而它们错了不会有任何报错 —— 对应的功能只是
永远不触发，看起来像"她今天没反应"。插件又跑在带鉴权的页面里，外部脚本连不上，所以自检必须由
插件自己在页面里提供。Console 里敲：

```js
__wisp.doctor()
```

返回当前页面里每条链路的真实情况：三个输入框钩子各命中几个、忙碌钩子、三个待处理面板、出错行、
亮暗状态、五个主题令牌的实际取值，以及一份 **`problems`** —— 只列**真的意味着功能失效**的条件。
缺席类信号不算问题：没有待处理项、没有出错行都是正常状态，把它们算成问题只会训练人忽略这份清单。

只读，无副作用。

**忙碌钩子会自解释**：它是唯一无法静态确认的（`aria-label` 来自语言表，不是源码字面量），
所以当它匹配不到时，报告会附上页面上实际存在的按钮 `aria-label` 采样 —— 一次调用就能看出
该匹配什么，不必再靠猜。

其余 `data-*` 钩子已在**已发布的 `app.asar`** 里逐个确认存在（`data-composer-input` ×1、
`data-question-key` ×1、`data-plan-review-key` ×1、`data-approval-key` ×2、`data-error`、
`data-ds-dark-theme`）—— 源码里有 ≠ 发行版里有，所以查的是发行版。

## 改形象（素材流水线）

**形象的唯一权威来源是 [tools/CHARACTER-PROMPT.md](tools/CHARACTER-PROMPT.md)** —— 逐字复用的提示词母版 + 四张姿态 + 完整生成参数。改形象 = 改那个文件、重新出图、再跑一条命令。

```bash
# 1. 按 tools/CHARACTER-PROMPT.md 的参数与提示词，为五个情绪各出一张【绿幕】图，存成 <mood>.png
# 2. 绿幕 → 抠图 → 四档素材，一步到位（任何一张抠图异常都会以非 0 退出）
#    --skin 决定输出到 assets/<skin>/，也就是新增一套可切换的皮肤
node tools/assets.mjs --from <绿幕母版目录> --skin <皮肤名>
#    如果手上只有【已经抠好的透明 PNG】（绿幕原图不在了），走这个，不重复抠图：
node tools/tiers.mjs --from <透明PNG目录> --skin <皮肤名>
# 3. 打进客户端半包
node build.mjs --tier=hi     # hi 档 = 2048x3072，与母版同尺寸，仅重新编码
# 4. 预检
node verify-wisp.mjs
```

三条硬约束（实测依据见 CHARACTER-PROMPT.md 与 NOTICE.md）：

1. **不要用服务端的透明背景。** 它会把浅蓝渐变的发梢与鲸尾当背景切掉，表现成"模型跑形"，几乎无法从结果反推。出绿幕、自己抠图 —— 只有 0.4%–0.7% 的边缘像素需要处理，发丝一根不丢。
2. **不要传参考图。** 形象靠提示词锚定；一条提示词只放一个角色。
3. **画风别写"高质量二次元插画"这种笼统说法**，它会推向韩系半写实并崩掉设定。

## 性能

一切数字都是在真实 Chromium 里量的（合成 10k 节点会话记录，headless、CPU 光栅，即**最不利**的一档）。计数与耗时都靠**包装原生 `querySelector`/`querySelectorAll`** 得到，不靠估算。可复现的探针：`node tools/perf.mjs`（浏览器是可选依赖，缺了会跳过并说明）。

### 稳态

| 指标 | 数值 |
|---|---|
| 动画帧使用量 | **0**（走 `timer` 服务，根本不挂帧循环） |
| 定时器 | 1 个 `interval`（反应轮询）+ 3 个 `timeout` |
| 反应轮询成本 | 每轮 3 次 `querySelector`，10 s 内共 **7.2–8.3 ms**（≈ **0.86 ms/轮**） |
| 每帧平均间隔 | 无插件 **4.194 ms** vs 挂载后 **4.217 ms** → **+0.023 ms**（4 轮交替重复） |
| 每秒 DOM 查询 | `querySelector` **1.6 次**（有输入框）/ **2.8 次**（无输入框，最悲观）；`querySelectorAll` **0 次** |
| DOM 查询耗时 | **0.72–0.83 ms/秒** ≈ 单核的 **0.07–0.08%** |
| 出错扫描 | **每跑完一轮一次**，10k 节点页面上实测 **0.017 ms**（不随轮询频率增长） |

**为什么是这个数量级**：每轮轮询查三次 —— 忙碌钩子、待处理面板钩子、以及输入框钩子。第三条只在输入框**尚未解析出来**时才查（解析一次后缓存）；页面里没有输入框时它是常驻的，所以 2.8 次/秒是**最悲观**的一档，1.6 次/秒才是真实应用的形态。

老实现是"每次都重新全量查一遍"：`querySelectorAll` 每次都调、1.27 ms/次。后来把输入框元素**解析一次后缓存**（仅在它离开文档时重新解析），忙碌判定从 4 条精确选择器改成 2 条子串选择器 —— 后者还能顺带匹配没见过的语言标签。

**帧开销必须交替重复测**：单次差值里的噪声就有 0.1 ms 量级（同一份代码两组测得 +0.127 与 −0.002），一次测量说明不了任何事。

### 一次性成本

- **挂载瞬间**有一次约 15–50 ms 的卡顿（headless CPU 光栅下）。来源是注入样式表触发的整篇样式重算 + 首次模糊光栅化，不是稳态开销；预热 1.5 s 后测 6 s，**没有任何一帧超过 20 ms**。
- **挂载一次性开销实测 19.3 ms**（5.2 MB 的包）。
- **包体积不是约束**：解析+执行 5.2 MB → 19.3 ms、8 MB → 28.4 ms、16 MB → 32.3 ms、24 MB → 46.5 ms，
  斜率约 **1.45 ms/MB**（次线性）。再加一整套皮肤（+1.1 MB）约 +1.6 ms。
  探针：`node tools/bundle-cost.mjs`。
- 28 张精灵图（**4 皮肤 × 7 情绪**）共 4.58 MB base64，挂载时只解码用到的 1 张，其余在 1.5 s 后预热。
- **解码后的内存**：一张精灵图是 `宽 × 高 × 4` 字节 —— 当前 1024×1536 档 **6.0 MB/张**，预热会把当前皮肤的五张全解出来（≈30 MB）；`--tier=hi` 是它的 4 倍。选档位不只是锐度问题。

### 已知的、没修的

- **rAF 兜底路径**在没有 `timer` 服务的壳里，只要还有任务待触发就会保持帧循环（拿不到 `setTimeout`，没有别的唤醒源）。真实 DSH 壳不走这条路 —— `window.__wisp.clock` 若不是 `timer-service` 就是它。
- 常驻的呼吸动画在 headless CPU 光栅下会让偶发单帧变长（4 次重复里最差 37 ms，平均值不受影响）。GPU 合成的真实窗口里这类 `filter` 通常不花钱。`prefers-reduced-motion` 会关掉全部动画。

## 配置

配置写在 profile 的 bundle patch 里（`~/.dsh/profiles/<profile>/cordis.patch.yml`，或本包 `cordis.patch.yml` 的 `insert` 行上），作为 `apply(ctx, config)` 的第二个参数。**全部可选，全部会被夹到合法区间**——写错只会退化成默认值，不会做出一个找不到或点不动的桌宠。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `right` | number | `26` | 距右边缘 px（仅首次落位；拖动过之后以记忆位置为准） |
| `bottom` | number | `46` | 距下边缘 px |
| `size` | number | `4` | 缩放，限制 `0.4–8`；默认绘制 560×840 CSS px |
| — | — | — | 菜单里调过的 `size` 会**记在本地**并活过刷新；但配置里显式写了 `size` 时以配置为准 |
| `sleepAfterMs` | number | `90000` | 静置多久打盹，限制 `5000–3600000` |
| `reactions` | boolean | `true` | 是否跟随 Agent 忙碌 / 输入框内容变情绪 |
| `persist` | boolean | `true` | 是否跨刷新记住位置 |
| `celebrate` | boolean | `true` | 一轮跑完是否庆祝一下 |
| `celebrateAfterMs` | number | `2500` | 只庆祝跑够这么久的轮次（避免每次小工具调用都跳） |
| `happyMs` | number | `1100` | 高兴状态持续多久 |
| `hidden` | boolean | `false` | 挂载时就是躲起来的（只能强制隐藏，叫回来走菜单或 `__wisp.show()`） |
| `chatterMs` | number | `0` | `>0` 时按此间隔随机说句话；`0` = 安静 |
| `careAfterMs` | number | `5400000` | 连续活动多久提醒你起来动动（90 分钟）；`0` = 关 |
| `milestones` | boolean | `true` | 今日轮次到里程碑时得意一下 |
| `memory` | boolean | `true` | 她记着你（一起多少天 / 习惯放哪 / 常穿哪套） |
| `wander` | boolean | `true` | 空闲时自己小幅踱步 |
| `wanderMs` | number | `45000` | 多久考虑溜达一次，限制 `5000–3600000` |
| `wanderRange` | number | `260` | 单次溜达最远距离 px，限制 `0–2000` |

例：

```yaml
- id: wisp
  name: "dsh-wisp"
  config:
    bottom: 90
    size: 1.2
    chatterMs: 300000
```

### 运行时 API

页面 Console 里 `window.__wisp` 可用：

```js
window.__wisp.say('你好')                 // 说一句
window.__wisp.mood('happy')               // idle | alert | attn | happy | sleep
window.__wisp.configure({ size: 1.5 })    // 部分更新，其余键保持不动
window.__wisp.move(200, 300)
window.__wisp.position                     // { x, y }
window.__wisp.resetPosition()              // 清掉记忆位置，回到右下角

window.__wisp.destroy()
```

`window.__wisp.clock` 直接告诉你这台机器走了哪条调度路径，排查时先看它。

## 平台契约（踩过的坑都在这）

### 1. 两个文件、两套契约

宿主 **import** `cordis.patch.yml` 里 `name:` 指向的包 —— 必须是合法 ESM，即 `lib/index.js`。
浏览器半包是**经典脚本**，由 `package.json` 的 `exports["./client"]` 定位、`/plugins` 路由投递，自己调用 `window.__ModuleLoader__.load({ id, factory })` 注册。

**patch 那一行写成 `dsh-wisp/client` 会导致 `failed to import`** ——宿主无法 import 经典脚本。

### 2. 六个全局是抛异常的陷阱

`setTimeout` / `setInterval` / `clearTimeout` / `clearInterval` / `fetch` / `require` 在客户端半包里被**抛异常的形参**遮蔽。所有时序因此来自 Client `timer` 服务：

```js
ctx.get('timer').timeout(fn, ms)   // → disposer
ctx.get('timer').interval(fn, ms)  // → disposer
```

`timer` 服务取不到时（老壳 / 无头壳）退回 `requestAnimationFrame` 截止时间表，**且只在有任务待触发时才挂帧**——原来那种常驻 60fps 帧循环会让桌面进程每秒白醒 60 次。

`ctx.get('theme')` 与 `ctx.on('theme/change')` 用来跟随明暗；`body[data-ds-dark-theme]` 是兜底（这是壳真的会写的属性）。

### 3. 精灵图必须走 `blob:`，不能直接给 `data:`

初版把 base64 data URI 直接赋给 `img.src`：插件"挂载成功"、DOM 正确、光晕正常，**图是碎的**。字节经校验无误，是这个壳拒绝 `data:` 作图片源。现在解码成 `Blob` 再取 object URL，拆解时 `revokeObjectURL` 释放，**并把缓存条目一起删掉**——blob 缓存是模块级的，而挂载是每次 apply 一次，只 revoke 不删键会让下一次挂载拿到已吊销的 URL，又变成碎图。

### 4. 一次性实例

`apply` 会先销毁已存在的 `window.__wisp`。HMR 重挂、重复行、以及注入版残留都会走到这条路径，否则会叠出第二只。

### 5. 反应信号取自 DOM 事实

- 忙碌：`button[aria-label*="停止"],button[aria-label*="Stop"]` —— 壳自己的「正在跑」按钮（zh 标签是"停止生成"，en 是 "Stop generating"）。用子串而不是枚举精确标签，是因为标签会被翻译，而且实测 2 条子串选择器比 4 条精确选择器便宜 40%，覆盖反而更宽；
- 输入框有字：`[data-composer-input]`（依次回退到 `textarea`、`[contenteditable="true"]`）——**解析一次后缓存**，只在元素离开文档时重新解析。

两者都是壳为自家用户渲染的东西，比内部服务契约更抗版本升级。

## 生成审计：素材从哪来，可自查

有人问"严查是否存在图生图"，我就把这件事做成了**可复查的文件**，而不是一句承诺。

### 为什么需要它

Maker 代理自己维护一张登记表（`<Maker 项目>/.maker/assets/generated-assets.json`），
记录每次生成的**工具名 / 提示词 / 时间 / 产物路径** —— 但它**不记参数**。
而 `generate_image` 与 `batch_generate_images` 是**允许**传可选 `reference_images` 的，
所以"没喂参考图"这件事，代理那边证不了。

### 这个日志记什么（`audit/generation-audit.jsonl`）

两类证据**分开记**，谁强谁弱一目了然：

| 字段 | 来源 | 强度 |
|---|---|---|
| `registry.tool` | **代理自己写的**（独立于本插件） | **硬证据**：`edit_image` 是唯一能做图生图的工具，工具名说了算 |
| `declared.reference_images` | 本项目调用前写下的参数 | **自我声明**，但写进哈希链、事后改不了，且写在调用之前 |
| `output.sha256` | 入包素材本身的哈希 | 可复查：事后有没有被改过 |
| `master.sha256` | 母版的哈希（开发机上） | 可复查母版是否被换过 |

每条记录都带 `prev` 指向上一条的 `hash` —— **改任何一条都会断链**，而断链会被预检抓住。

### 怎么用

```bash
node tools/audit-log.mjs --verify                 # 校验链 + 重算入包素材哈希
node tools/audit-log.mjs --declare <manifest>     # 生成前：登记将要发出的参数
node tools/audit-log.mjs --confirm <manifest>     # 生成后：并入代理登记表 + 记产物哈希
```

预检里已有两条常驻断言（`3z` 段）：链校验通过且覆盖全部入包素材、且**审计中不得出现 `edit_image`**。

### 它证明了什么、没证明什么

- **证明了**：入包素材逐字节等于记录在案的那次调用的产物，此后没被改过；那些调用在代理登记表里
  用的是 `generate_image` / `batch_generate_images`，**不是** `edit_image`。
- **没证明**：对**回溯补录**的记录（本功能上线前的 35 个素材），没有"当次自我声明的参数"，
  因为那时还没有这个日志 —— 它们的 `declared` 字段是 `null`，如实标注，不冒充。
  只有今后新生成的素材才会带上完整的 declare + confirm 两条记录。
- 另外：即使某次真的传了参考图，代理也不会在登记表里留下痕迹（它不记参数）——
  所以"没喂参考图"最终依赖的是**自我声明 + 声明不可事后篡改**，而不是第三方取证。这一条必须说清楚。

## 更新：能做什么、为什么不能自己更新

### 先说结论

- **检查更新：能。** 走平台给的服务 `ctx.web.fetch`（DSH 自己的 `web_fetch` 工具用的就是它）。
- **安装更新：不能。** 插件既没有文件系统、也没有包管理器；DSH 的安装器没有以可注入服务的形式
  暴露给插件。安装仍然要走 DSH 自己的插件列表。

为什么必须绕这么一圈 —— 两边的限制都查到源码级：

- **浏览器半包**的 `fetch` 是教学陷阱（一调用就抛），原文写着 "network belongs to the HOST half"。
- **宿主半包**跑在 **vm 沙箱**里：`harness` 只有 `defineTool / registerTool / handle`，
  沙箱里还有 `nodeApiTraps()` 把 Node API 全挡了，允许的 `ctx` 动词白名单里**没有网络与文件系统**。

**为什么要读两个源（npm + GitHub）取更高版本**：npm 的注册表是权威源，但发布可能长时间卡在它的
**暂存区**里 —— 实测：`PUT 202`（已受理）之后等了 18 分钟，注册表和 tarball **仍然 404**，
而同版本号重发被拒（`409 Cannot publish over previously staged version`）；
同期 GitHub 的 `package.json` 是**立刻**更新的。
所以检查同时读两个源、**取版本号更高的那个** —— 这样无论 npm 有没有追上都是对的。
「npm 优先、GitHub 兜底」在这里是错的 ✗：它会读到 npm 那个旧号，然后告诉你"已经是最新的"。

所以网络只能走**服务**：宿主半包 `inject: { optional: ['web'] }`，用 `ctx.web.fetch(...)` 抓远端
`package.json`，再用 `harness.handle('checkUpdate', …)` 注册；浏览器半包 `host.call('checkUpdate')` 调。
**客户端那边一点网络都没碰** —— `fetch` 陷阱原样留着。

**`web` 声明为可选（optional）不是风格问题**：硬依赖一个没加载的服务会让 fiber 永远 `waiting`，
她会直接从界面上消失。预检里有两条断言专门盯着这件事（必须可选、不能必需）。

> 更正：上一版 README 写的是"这个插件不能检查更新" —— 那个结论错了。它建立在
> "服务目录里没有网络类服务"上，而我漏看了 `ctx.web`：它是**注册表式**服务，提供者
> `web-fetch-http` 只往里 `registerFetchProvider`，所以按 `provide("web")` 搜是搜不到的。

### 那这个插件做了什么

都是**沙箱允许范围内真能做到的**：

| 能力 | 怎么用 |
|---|---|
| **真的去查更新** | 菜单「版本与更新」经 `host.call` → 宿主半包 → `ctx.web.fetch` 抓远端 `package.json`，
  比对后说「有新版本了：X」或「已经是最新的了」；查不到就如实说「更新没查成」 |
| **报版本** | 菜单「版本与更新」说一句「我是 1.24.0。<这一版做了什么>」；`__wisp.version` / `__wisp.doctor().update` 也能读 |
| **更新感知** | 她记住上次见到的版本（localStorage）。**版本变了就说一句「我更新到 … 了」**；第一次安装不吭声（那时她不是更新，是刚来） |
| **复制包名** | 同一项会把 `dsh-wisp` 复制到剪贴板，方便在 DSH 的插件列表里粘贴安装。**没有剪贴板权限时静默降级**成只说话，不报错 |
| **能力边界如实上报** | `doctor().update` 里有 `canSelfUpdate: false` 和 `why`（写明沙箱原因） |

### 真正更新它的路径

1. DSH 的插件列表 →「按插件包名安装」/ 更新（DSH 自己的「检查更新…」也在那里）；
2. 或对本包目录重新 `npm i` / `npm pack` 后安装；
3. 更新后重载页面 —— 她会自己发现版本变了并说一句。

### 预检里的守卫

`WHATS_NEW` 必须写着**当前版本**，否则预检红 —— 这样"这一版做了什么"不会静默过期。
另外 `canSelfUpdate === false`、`hint` 里必须含包名、`why` 里必须说明沙箱原因，都有断言盯着。

### 1.33.2

**修「她在屏幕角落时，子菜单跟着偏」。** 现象是：右下 / 左下时子面板整体**偏下**，
右上时**压住主菜单**一部分。

根因只有一句：**我用了菜单"请求"的位置，而不是"实际"的位置。**

菜单在视口边缘会被**夹取**（`clamp` 进 `vw()/vh()`）：

- 她在**右下 / 左下**时，菜单会被**往上推** → 实际 `top` 比请求的小 → 子面板却按请求的 `top` 算 → **偏下**；
- 她在**右上**时，菜单会被**往左推** → 实际 `left` 比请求的小 → 子面板按请求的 `left` 算 → 横向也偏 → **压住菜单**。

而且越靠角落、夹取越多、偏得越厉害 —— 正是观察到的规律。

改法就是读`menuEl.style.left/top`（菜单真实的图层坐标，夹取之后的值），
横向仍用"菜单宽度 + 面板宽度"、纵向仍用"行相对菜单的偏移"，这两者本来就与坐标系无关。

**顺便把这道防线补成四个角落各测一遍**（`tools/smoke.mjs`）：她先站到每一角，
再开菜单、悬停分组行、量三个矩形的相对关系，断言
「面板在菜单**旁边**」「在视口内」「与它所属那一行**对齐**」。
用户就是这样发现问题的，所以这条检查直接照着他的操作路径写。

实测四个角落：面板始终在菜单旁边（右侧角落翻到左边），`panel.t` 与 `row.t` **完全相等**。

**修「子菜单遮住主菜单」。** 上一版的定位是错的，而且错得不显眼 —— 面板确实"在旁边"，
只是**压进菜单十几个像素**。现在实测两矩形完全不重叠（右缘 1123 / 菜单左缘 1125）。

根因有三层，都是"拿了不该拿的数字"：

1. **混用了两套坐标系**：菜单的 `left/top` 是**图层坐标**，而 `getBoundingClientRect()`
   给的是**视口坐标**。二者只在图层恰好从 (0,0) 开始时相等。
2. **量了刚 append、还没布局的面板** ✗：那一刻它的宽度是 **0**，
   于是所有基于它的校正被守卫挡掉，位置就停在估算值上（实测就是这样一直没生效）。
3. **宽度算错**：CSS 写 `width:184px` 但没写 `box-sizing` ✗ →
   默认 content-box 再加 `padding:6px` + `border:1px` → 实际 **198**，
   而翻转算式里用的常量是 178 —— 差了 20 像素，正好压住菜单。

**现在的做法**（不可能算错的那种）：**只用量层坐标 + 宽度**。

- 面板宽度**固定**（`box-sizing:border-box; width:184px`）→ 常量就是真宽度，不用量；
- 横向：`x = 菜单left + 菜单宽度 + 2`，越界则 `x = 菜单left − 面板宽度 − 2`；
- 纵向：用"行矩形相对菜单矩形的**偏移**"→ `rr.top - mr.top` ——
  相对量与坐标系无关，而且自动带上头部/分隔线的高度（估算少了它，差了 28px）；
- 入场动画从 `scale` 改成**纯淡入**：带 scale 的动画会让 `getBoundingClientRect()`
  量到缩放后的矩形，这是第 2 条坑的一部分。

**另外补了一道之前缺的防线**：冒烟里加了**真浏览器**的几何检查 ——
「面板在菜单**旁边**（不是上面）」「在视口内」「与它所属那一行对齐」。
假 DOM 没有布局，这三条**测不到**，而这个 bug 恰好只存在于布局里 ——
所以它才会一路发布出去。

预检 529 项沿用；冒烟 53 → **57 项**。

### 1.32.0

### 1.32.0

**分组改成悬停展开、移开收起**（点一下仍然是"钉住"）。

这一条本来就是标准交互，上一版只做了"点开／点关"，属于设计盲区。补上之后，
真正要小心的地方不在于"加个 mouseenter"，而在于下面这几条 —— 少一条都比不做更糟：

| 细节 | 为什么必须 |
|---|---|
| **展开有延迟**（140 ms） | 鼠标只是**路过**那一行就展开 = 抖动。这就是 hover intent。 |
| **移开有宽限**（260 ms） | 斜着往子项移动时，中途不能收。 |
| **子项与标题在同一个悬停区**（`div.wisp-menu-group`） | 从标题移到子项**不该算移开**。这是这类交互最常见的翻车点。 |
| **点击 = 钉住** | 悬停是预览、点击是决定。点开的那一组鼠标移开也不关，再点一次才收起。 |
| **触屏不触发悬停** | 判 `pointerType`。不判的话手指一碰就会莫名其妙展开。 |
| **焦点在那一组里时不关** | 否则键盘用户正操作着，鼠标一动组就没了。 |
| **手风琴** | 悬停到另一组会解除上一组的钉住 —— 同时开两组看不清。 |

**顺手抓到一个真 bug**：焦点保护第一版写的是"焦点还在菜单里就不许关" ——
而菜单**一打开就会把焦点放到第一项**，所以那条件**永远为真**，
悬停收起等于**永远不会触发**。改成只看"焦点在不在**这一组**里"。
第一版还用了一个"组名 → 元素"的映射，实测和重画后的 DOM 对不上（组照样关）；
现在改成从焦点**向上走**、遇到带 `data-group-block` 的祖先就算命中 —— 不依赖任何外部映射。

预检 502 → **524 项**：延迟、宽限、路过不展开、子项在同一悬停区、
触屏不悬停但点击可用、点击钉住、再点收起、手风琴、焦点保护、焦点离开后规则恢复。
