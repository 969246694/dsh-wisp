# 走路动作：开工前的准备（静态图 + 帧动画）

> **这一版只做准备，不生成任何素材。** 下面每一节都以「生成那天照着做就行」为标准：
> 槽位、时序、朝向、提示词逐字稿、接线点、预检断言、成本、执行顺序。
> 结论先给：**这套东西里唯一需要现在就定死、定了就不能改的是第 3 节（时序）** ——
> 它决定素材要画成什么、生成时提示词怎么写、以及客户端那几个常数取多少。

---

## 0. 结论摘要

| 决定 | 值 | 理由 |
|---|---|---|
| 姿态名 / 槽位 | `walk` → `assets/<skin>/walk.webp`、`assets/motion/<skin>_walk.webp` | 沿用现有约定（静态图进包内联，动图走 `/wisp-motion/` 路由） |
| 走一个周期 | **850 ms**，即 `1700 / 2` | 她自己溜达一次的滑行是 **1700 ms**（`glideTo`），必须让它等于**整数个周期**，否则停下来那一帧永远停在迈到一半 |
| 素材帧率 / 帧数 | **25 帧一个周期 @ 34 ms**；先出一条 **50 帧 = 2 个周期 = 1700 ms** | 97 是质数，41 ms 下**任何**帧数都凑不出整数周期 → 走路素材必须是**声明过的例外**（和 96 帧那两条同一个机制） |
| 朝向 | 素材一律**纯侧面、朝右**；不要转身、不要换朝向 | 镜像由 `scaleX(-1)` 做；转身会把镜像变成「倒着走」 |
| 静态图姿态 | **接触相位**（前后脚都在地上、重心前移），不是迈步中间 | 它同时是帧动画的**首帧与末帧**（`first_last_frame`），同一个相位才能无缝接回 |
| 生成参数 | 静态图沿用 v2（`gpt` / 4K / 2048x3072 / 2:3 / high / 不传参考图）；动画 `first_last_frame`，首末同一张 | 房规，见 `tools/CHARACTER-PROMPT-V2.md` 与既有 19 条素材 |
| 分阶段 | ① `canon` 一套打通 → ② 其余 18 套静态图 → ③ 其余套的动画按需 | 先把契约跑通，再铺量（铺量是重复劳动，契约错了要重来） |

## 3. 时序契约（**准备的重点，改起来最贵**）

### 3.1 现状（三个硬编码的数）

| 量 | 值 | 出处 |
|---|---|---|
| 一次溜达的滑行时长 | **1700 ms** | `lib/client.template.js` 的 `glideTo()`（`clock.after(1700, …)`） |
| 滑行距离 | 最远 260 px（`full`）/ 104 px（`subtle`，`MOTION_WANDER.range = 0.4`） | `DEFAULTS.wanderRange` / `MOTION_WANDER` |
| 溜达触发 | 空闲时每 45 s 考虑一次（`wanderMs`），`subtle` 档 ×2.5 | `syncWander()` |

也就是：她**每次走 1.7 秒**，最远 260 px → 平均 153 px/s。

### 3.2 为什么必须「整周期对齐」

动画是循环播放的，而滑行是**定时结束**的。两者对不齐时，她会在**迈步迈到一半的那一帧上直接切回站姿** ——
这是这套动作里最刺眼的一处，而且没有任何报错、日志、DOM 变化能提示它。

所以：**1700 ms 必须是走路周期的整数倍。** 取 `周期 = 1700 / 2 = 850 ms`（一次溜达正好两个周期）。

### 3.3 帧预算：97 帧这条房规必须破一次

现在所有素材钉在 720×1280 / **97 帧 / 41 ms**（≈ 3977 ms）。97 是质数，所以 41 ms 下**不存在**「整数个
850 ms 周期」的排法（97 的因子只有 1 和 97）。于是走路素材要当**声明过的例外** —— 和 `canon_work` /
`swim_work` 那两条 96 帧一样：点名、写原因，而不是把 97 悄悄挪成别的数。

| 量 | 值 | 备注 |
|---|---|---|
| 每周期帧数 | **25 帧** | 25 × 34 ms = 850 ms ✓ |
| 每帧时长 | **34 ms**（≈29.4 fps） | 比 41 ms 更顺；走路这种连续位移不适合 24 fps 以下 |
| 素材总帧数 | **50 帧**（2 个周期） | 50 × 34 = 1700 ms = 一次溜达 |
| 文件体积 | 预计 **0.8–1.5 MB** | 现有 4 s 素材 2.5–3.8 MB，帧数减半 → 更小，远低于 12 MB 上限 |

### 3.4 脚踏滑（foot slide）预算

每周期她要前进的距离 = 滑行距离 ÷ 周期数：

| 动作幅度档 | 溜达距离 | 对齐后的周期数 | 每周期前进 | 素材里的步幅应画成 |
|---|---|---|---|---|
| `full`（默认） | 260 px | 2 | **130 px** | ≈ 身高的 12%（1050 px 高时约 130 px） |
| `subtle` | 104 px | 1（不足一个周期算一个） | **104 px** | 同上；差 20% 以内看不出来 |

**客户端要记住的两个数**（第 6 节接线用）：`WALK_CYCLE_MS = 850`、`WALK_FRAMES_PER_CYCLE = 25`。
滑行时长改成 `ceil(距离 / 每周期距离) × 850`，而不是写死 1700 —— 这样 `subtle` 档也不会停在半步上。

### 3.5 素材里帧怎么放

- 帧 0 = 接触相位（左脚在前）—— **与静态图同一张**
- 帧 24 = 接触相位（右脚在前）
- 帧 25 … 49 = 第二个周期；循环时接回帧 0

**不要**在末尾复制一帧充数（既有素材「首帧 = 尾帧」是视频模型的喂法决定的，代价是每次循环多停一帧）。
走路素材是切出来的：直接切满 50 帧、循环接回帧 0 最干净；环缝指标量的正是 `n-1 → 0` 这一步。

## 4. 朝向与镜像契约

- 素材是**纯侧面（profile）**，文件里一律**朝右**，全片**不转身、不改变朝向**。
- 页面上的左右由 `scaleX(±1)` 做（`paint()`），而现在 `facingOf()` 是按**她在屏幕哪半边**决定的（`lib/client.template.js:1708`）。
- **这条对走路是错的**：站在右半边往左溜达时镜像不动 → 她会**倒着走**。
  接线时：滑行期间朝向取 `sign(dx)`，滑行结束后交还给 `facingOf()`。
- 侧面立绘比正面窄，客户端按 `bottom center` 对齐，所以**脚底线要和其它八张一致** ——
  不一致她就会在走路时「飘」起来或陷下去。

## 5. 生成配方

### 5.1 静态图（第 9 个姿态）

沿用 v2 的全部参数与禁令（`tools/CHARACTER-PROMPT-V2.md` 第 1 节）：`model=gpt`、`resolution=4K`、
`target_size=2048x3072`、`aspect_ratio=2:3`、`quality=high`、`thinking_level=high`、**不传参考图**、
**一张图一次调用**、绿幕（`rgb(0,255,0)`，必须放最前）。

新增**第 9 段姿态段**（与其它八段并列，逐字可粘贴）：

```
【姿态：走路（侧面）】她正在**向画面右侧行走**的**纯侧面**姿态：身体与视线都朝向画面右侧，
头部与肩、髋、膝、踝全部呈**侧影**，不要正面、不要四分之三侧、不要回头看观众。
① 双脚都在地面上、一前一后：前脚整只脚掌落地、后脚脚跟微微抬起，两脚之间大约一个半脚长；
② 重心略前移，上半身自然直立、微微前倾 5° 以内，不要弯腰、不要后仰；
③ 手臂自然前后摆动（与腿相反），手臂不要抬平、不要甩开；
④ 裙摆 / 浴衣下摆 / 长外套下摆被行走带起一点，**但不能挡住任何一只脚**；
⑤ 鲸尾在身后自然下垂、随步伐略向后摆，**不能挡住双腿**；
⑥ 长袖、飘带、挂饰都不能遮住脚、膝、髋的轮廓。
```

**末尾清单（v2 第 5 节）要加的两条** —— 清单才是真正被执行的通道：

```
⑫ 走路的**侧面**姿态必须是纯侧影：两只眼睛只能看到一只，鼻尖朝画面右侧，双脚一前一后都完整可见；
⑬ 双脚、膝盖、髋部都不能被裙摆、外套下摆、鲸尾、长袖或飘带挡住 —— 行走的步态必须看得清。
```

### 5.2 帧动画

房规是 `first_last_frame`：**首帧与末帧喂同一张图**（就是这张 walk 静态图），中间由模型补出运动。

| 参数 | 值 | 说明 |
|---|---|---|
| `mode` | `first_last_frame` | 两张图都是同一张 walk 立绘 |
| `duration` | `4` | 直出 4 秒走路，之后再切到 2 个周期 |
| `resolution` | `720p` | 与既有素材一致（720×1280） |
| `ratio` | `9:16` | 竖版，和素材一致 |
| `generate_audio` | `false` | 帧动画不需要声轨 |
| `model` | 默认（2.0） | 不超 10 秒、不用 2.5，避免二次确认流程 |

提示词（逐字稿）：

```
纯侧面视角、镜头完全固定不动的行走循环：角色**朝画面右侧**连续行走，
身体与头部始终是**纯侧影**，全程**不转身、不回头、不改变朝向、不改变机位、不缩放**。
脚步保持均匀节奏，左右腿交替迈步；手臂与腿自然反向摆动。
背景**始终是纯绿色**（严格 rgb(0,255,0)），从头到脚均匀铺满，不要阴影、不要渐变、不要其它物体。
结尾必须回到与开头**完全相同的那一个迈步相位**（同一只脚在前、双脚位置一致），使首尾可以无缝循环。
```

### 5.3 出包流程（每条素材都一样）

1. 绿幕母版 → 抠图 → 720×1280 → 收敛脚底线 → `assets/<skin>/walk.webp`；
2. 视频 → 逐帧抠像 → 切掉首尾多余帧 → **把每帧时长改成 34 ms** → 切满 50 帧 → `assets/motion/<skin>_walk.webp`；
   - `tools/motion-trim.mjs` 现在只会**丢尾部整帧**（改容器、不重编码）。**要加一个改时长的开关**：
     ANMF 块 `+12` 起 3 字节小端就是该帧时长（ms），改完把 RIFF 长度字段照旧写对即可，约 20 行；
3. `node tools/motion-seam.mjs` 量环缝 → 比值 > 1.2 就重切或重生成，≤ 1.2 记进表（连同它量自的字节 sha）；
4. `node tools/audit-log.mjs` 记一条生成审计（模型、参数、seed、母版文件）；
5. `node build.mjs && node verify-wisp.mjs` 必须全绿（第 7 节的断言要先加上）。

## 7. 预检要加的断言

1. **姿态清单**：每套皮肤要么**九张全有**，要么九张全无 —— 不许「17 套有、2 套没有」的半成品状态；
2. **时序**：滑行时长必须落在整周期上（构造几个距离，断言落点是 `WALK_CYCLE_MS` 的整数倍，`subtle` 档也不例外）；
3. **朝向**：向右溜达时 `scaleX(+1)`、向左时 `scaleX(-1)`（用假 DOM 的位置 + `glideTo` 直接测）；
4. **帧预算**：`canon_walk` 的 50 帧 / 34 ms 必须在**声明表**里，且理由非空（照 96 帧那两条的反向断言写）；
5. **环缝**：`canon_walk` 的比值 ≤ 1.2，且数字与字节 sha 绑定（重切一次就作废）；
6. **静默降级**：没加 `walk.webp` 的皮肤，`setMood('walk')` 必须退回 idle，不许出现空盒子。

## 8. 成本与风险

**成本**

- 包体：静态图内联进 `lib/client.js`。现在 23.4 MB / 152 张（平均约 114 KB，canon 单张约 150 KB）。
  19 套 × 1 张 ≈ **+2.2 MB（+9%）**；只做 canon 是 **+150 KB**。
- 素材：动画约 1 MB/条（50 帧），比现有 4 秒素材小一半；19 条全做 ≈ +19 MB（现在 58 MB）。
- 生成：静态图 19 次调用（每套 1 张）；动画 1 次/套（4 秒直出后切）。

**风险**

| 风险 | 症状 | 预防 |
|---|---|---|
| 停在半步上 | 每次溜达结束她都定在迈步中间 | 第 3 节整周期对齐 + 预检第 2 条 |
| moonwalk | 往左走却朝右 | 第 4 节 + 预检第 3 条 |
| 脚踏滑 | 步子与位移不同步，像在冰上滑 | 每周期前进约 130 px 的画法 + `subtle` 档取整周期 |
| 转身 / 回眸 | 循环里出现转过来又转回去 | 提示词写死「不转身、不回头、机位固定」 |
| 裙摆鲸尾挡腿 | 步态看不清，动起来像在飘 | 姿态段 ④⑤⑥ + 末尾清单 ⑫⑬ |
| 环缝 | 每圈顿一下 | `tools/motion-seam.mjs` 量；> 1.2 不许进包 |
| 97 帧房规 | 帧数被悄悄改掉 | 声明表 + 反向断言（预检第 4 条） |
